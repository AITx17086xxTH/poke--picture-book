# 要件定義書：ポケモン図鑑アプリ

最終更新：2026-11-23

## 1. 目的・背景
- プログラミング学習（React / TypeScript / 外部API / Firebase）が主目的
- 就職・転職活動で見せるポートフォリオ作品として公開する
- 「動いて、説明できる」ことを重視する

## 2. 想定ユーザー
| ユーザー | 想定する見方 |
|---|---|
| 採用担当・面接官 | 短時間でURLを開き、動作とREADMEを確認する |
| ポケモン好きの一般ユーザー | 図鑑として検索し、自分のパーティを組む |

## 3. スコープ
### 対象（作る）
- ポケモン図鑑（一覧・検索・絞り込み・詳細）
- パーティ編成（最大6匹）
- ログインとクラウド保存

### 対象外（作らない）
- 対戦・ダメージ計算機能
- 全言語対応（まずは日本語表示を優先）
- 広告・課金などの収益化
- 他ユーザーとのパーティ共有（余裕があれば将来検討）

## 4. 機能要件
優先度：◎必須 ○重要 △あれば

| ID | フェーズ | 優先度 | 機能 | 内容 |
|---|---|---|---|---|
| F-01 | 1 | ◎ | 一覧表示 | ポケモンをカード形式で表示（画像・名前・図鑑番号） |

| F-03 | 1 | ◎ | タイプ絞り込み | 選んだタイプで一覧を絞る |
| F-04 | 1 | ◎ | 世代絞り込み | 選んだ世代で一覧を絞る（検索・タイプとの併用可） |
| F-05 | 1 | ◎ | 詳細ページ | 能力値（種族値）・タイプ・特性・身長体重などを表示 |
| F-06 | 2 | ○ | パーティ編成 | 最大6匹まで追加・削除。重複可否は設計時に決定 |
| F-07 | 2 | ○ | ブラウザ内保存 | localStorageでパーティを保持 |
| F-08 | 3 | ○ | Googleログイン | Firebase Authenticationを使用 |

※お気に入り機能はパーティ編成に統合する。

## 5. 非機能要件
| 区分 | 内容 |
|---|---|
| 表示 | スマホでも崩れない（レスポンシブ） |
| 信頼性 | API通信に失敗しても画面が壊れない |
| 性能 | 初回表示を待たせすぎない（取得件数の絞り込み・キャッシュを検討） |
| コスト | すべて無料枠内で運用（Firebaseは無料のSparkプランを基本とする） |
| セキュリティ | Firebaseのキー管理・Firestoreのアクセスルールで他人のデータを守る |
| 保守性 | TypeScriptで型を付け、コンポーネントを小さく分ける |

## 7. 開発フェーズ
1. フェーズ1：図鑑（一覧・検索・絞り込み・詳細）
2. フェーズ2：パーティ編成（localStorage）

4. フェーズ4：仕上げ・公開

## 8. 制約・リスク
- **権利**：ポケモンの名称・画像の権利は権利者に帰属する。非営利・学習目的に限定し、READMEに非公式である旨を明記する。規約は随時自分で確認する。
- **API制限**：PokéAPIは無料の公開APIのため、過度なアクセスを避ける（取得データの再利用・キャッシュを設計に含める）。
- **Firebase無料枠**：Sparkプランは無料枠を超えると該当サービスが停止する。上限の最新値は実装時に公式ドキュメントで確認する。
- **学習負荷**：TypeScriptとFirebaseを同時に学ぶため、フェーズを分けて段階的に進める。
- **PCの空き容量**：開発PCの空きが少ない（約5GB）。不要ファイルの整理を行う。
